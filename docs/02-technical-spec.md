# مُرافعة — وثيقة المواصفات التقنية (Technical Specification)

> **الغرض:** المخطّط الذي تبني منه النسخة الحقيقية مع كلود كود. يترجم النموذج والوثائق (نموذج البيانات، الصلاحيات، الشاشات، القواعد) إلى بنية قابلة للتنفيذ.
> **الجمهور:** أنت (مطوّر فردي) + كلود كود.
> **اقرأ معها:** `03-data-model.md` · `04-permissions-matrix.md` · `05-screens-inventory.md` · `06-business-rules.md`.

---

## 1. النطاق والمبدأ

النسخة الحقيقية تُبنى من الصفر بمعمارية إنتاجية، والنموذج (`prototype/`) **مرجع بصري وسلوكي فقط** — لا يُحوَّل كود HTML الحالي مباشرةً. الأولوية: الصحّة القانونية، إقامة البيانات داخل المملكة (PDPL)، وفرض الصلاحيات على الخادم.

**القاعدة الذهبية:** أي قرار يخالف هذه الوثيقة أو الوثائق المرفقة → الوثيقة تكسب. النموذج يبيّن الـ UX، لا الحقيقة التقنية.

## 2. المعمارية (نظرة عامة)

```
┌─────────────────────────────────────────────┐
│  Next.js (App Router) — TypeScript           │
│  الواجهة (RTL/AR) + server actions/API       │
└───────────────┬─────────────────────────────┘
                │
   ┌────────────┼─────────────┬───────────────┐
   │            │             │               │
┌──▼───┐   ┌────▼────┐   ┌────▼─────┐   ┌─────▼──────┐
│ Auth │   │ Prisma  │   │ RAG +    │   │ Integrations│
│ OTP  │   │ Postgres│   │ Citation │   │ Najiz/Nafath│
│      │   │+pgvector│   │ Gate     │   │ ZATCA/WPS   │
└──────┘   └─────────┘   └────┬─────┘   └────────────┘
                              │
                         ┌────▼─────┐
                         │ Claude   │
                         │ (Vertex) │
                         └──────────┘
   كل ما سبق داخل Google Cloud — منطقة الدمام (إقامة بيانات)
```

**الطبقات:** عرض (React/RTL) → خدمة (server actions/route handlers، فيها فرض الصلاحيات والقواعد) → بيانات (Prisma/Postgres) → خدمات خارجية (الذكاء، التكاملات). المهام الخلفية عبر Cloud Tasks/Scheduler.

---

## 3. الـ Stack (التفصيل)

- **Runtime/Framework:** Next.js (App Router) على Node LTS، TypeScript بوضع `strict`.
- **UI:** Tailwind CSS + shadcn/ui (Radix) مع دعم RTL؛ خطوط IBM Plex Sans Arabic + Amiri؛ design tokens من ثيم النموذج (`--bench`, `--gold`, `--advocate`, `--parch`).
- **i18n:** كل النصوص عربية عبر طبقة i18n (لا نصوص مكتوبة في الكود مباشرة) — لتسهيل المراجعة ومستقبلاً الإنجليزية.
- **DB:** PostgreSQL (Cloud SQL، الدمام) + امتداد `pgvector`.
- **ORM:** Prisma (مخطّط واحد مصدر الحقيقة + migrations).
- **AI:** Claude عبر Vertex AI (نقطة إقليمية).
- **Auth:** Auth.js (NextAuth) + جلسات + OTP.
- **Jobs:** Cloud Tasks + Cloud Scheduler.
- **Storage:** Google Cloud Storage (الدمام) للمستندات وملفات PDF/WPS.
- **Hosting:** Cloud Run.
- **Observability:** Cloud Logging/Monitoring + Sentry (تتبّع الأخطاء).

> **ملاحظة:** ثبّت إصدارات الحزم في `package.json` وقت البدء، وأعد التحقق من توفّر مناطق الاستضافة (تتغيّر) قبل الإنتاج.

---

## 4. طبقة البيانات

- المخطّط الكامل في `03-data-model.md`. **طبّق توصيات التطبيع:** مفاتيح أساسية/أجنبية بدل الربط بالأسماء، جدول وصل لـ `cases ⇄ users`، فصل `fee`/`hearings`/`timeline` لجداول، فصل حساب الأمانات (`TRUST`) عن الإيرادات.
- **حقول إلزامية لكل جدول:** `id` (UUID) · `created_at` · `updated_at` · `created_by` · `deleted_at` (حذف ناعم، يطابق سلة المحذوفات في النموذج).
- **المال يُخزَّن بوحدات صغرى صحيحة (هللات/integer)** لا بأرقام عشرية — حماية من أخطاء التقريب في المالية.
- **المعاملات (transactions):** كل عملية مالية (فاتورة + بنود + ضريبة، قيد محاسبي، حركة أمانة) داخل transaction واحدة.

---

## 5. تصميم الـ API

- نمط: route handlers / server actions، RESTful، استجابات JSON موحّدة `{data, error}`.
- **كل نقطة نهاية تفحص الصلاحية أولاً** (الطبقات الثلاث من `04-permissions-matrix.md`) قبل أي منطق.
- التحقق من المدخلات بـ schema (Zod) على حدود الخادم.
- ترقيم/تصفية موحّدة للقوائم.
- كل عملية حسّاسة تُسجَّل في `AUDIT`.

## 6. الذكاء القانوني — القاعدة المعرفية + بوابة التحقق من الاستشهاد ⚠️ (الأهم)

هذا **غير موجود في النموذج** وهو أخطر متطلب. أي مخرَج قانوني (المساعد، ساحة المرافعة، تحليل القضية) يمرّ عبر هذا المسار **إلزامياً**:

```
سؤال المستخدم
   ↓
استرجاع (retrieval) من القاعدة المعرفية المغلقة (pgvector)
   ↓
توليد بـ Claude — مقيّد بالمصادر المسترجَعة فقط
   ↓
بوابة التحقق: كل استشهاد (مادة/نظام/سابقة) يُطابَق آلياً
   مع مصدر فعلي في القاعدة. أي استشهاد بلا مصدر → يُحجَب/يُعلَّم
   ↓
العرض مع روابط المصادر + إخلاء «استرشادي لا فتوى»
```

**المكوّنات:**
- **القاعدة المعرفية المغلقة:** الأنظمة واللوائح والسوابق السعودية، مُقطّعة (chunked) ومُفهرسة في `pgvector`. **لا يستشهد الذكاء بشيء خارجها.**
- **التوليد المقيّد:** prompt يُلزِم Claude بالاعتماد على المصادر المسترجَعة فقط، ومنع اختراع أرقام مواد/أحكام (الضابط الموجود في النموذج يصير برمجياً صارماً).
- **بوابة التحقق البرمجية:** بعد التوليد، تُستخرَج كل الإشارات النظامية وتُطابَق مع معرّفات المصادر. غير المطابق يُحجَب. تُسجَّل نتيجة التحقق.
- **ساحة المرافعة:** الأطراف الثلاثة (محامينا/الخصم/القاضي) كلها تمرّ عبر نفس البوابة.
- **إقامة البيانات:** الاستدعاء عبر Vertex AI إقليمياً؛ وبيانات القضية في الـ prompt تُعامَل كبيانات شخصية (انظر §9).

---

## 7. التكاملات (تحلّ محل المحاكاة البصرية)

كلها بنمط **adapter** بواجهة موحّدة، مع تخزين بيانات الاعتماد بأمان (Secret Manager) ومعالجة فشل/إعادة محاولة:
- **ناجز (Najiz):** تصنيفات القضايا، الجلسات، الحالة الإجرائية.
- **نفاذ (Nafath):** التحقق من الهوية للدخول/التوثيق.
- **زاتكا (ZATCA/فاتورة):** الفوترة الإلكترونية المتوافقة (الفاتورة الضريبية، رمز QR، التقديم).
- **WPS:** ملف حماية الأجور (عبر البنك/مُدد) من مسيّر الرواتب.

> كل تكامل يحتاج عقد API موثّقاً + بيئة اختبار قبل الربط. تُبنى كوحدات مستقلّة قابلة للتعطيل (مثل `INTEGRATIONS` في النموذج).

---

## 8. المصادقة والصلاحيات

- **الدخول:** OTP عبر الجوال/واتساب (يطابق `loginSendOtp`/`loginVerify`)، تسليم عبر مزوّد سعودي. جلسات آمنة (httpOnly cookies). نفاذ للتحقق الرسمي لاحقاً.
- **الصلاحيات:** الطبقات الثلاث من `04-permissions-matrix.md` **مفروضة على الخادم**: وصول الوحدة + منع الحقل + نطاق الصفوف. لا «god mode» — كل جلسة لها دور صريح، والمالك دوره «شريك».
- جدول `roles`/`permissions`/`field_permissions` قابل للتحرير من شاشة الصلاحيات.

---

## 9. الأمان وحماية البيانات (PDPL)

- **إقامة البيانات داخل المملكة:** قاعدة البيانات، التخزين، والمعالجة في منطقة الدمام.
- **التشفير:** أثناء النقل (TLS) وفي السكون (at rest).
- **المعالجة عبر الحدود للذكاء:** بيانات القضية بيانات شخصية؛ استخدم نقطة إقليمية، وقلّل الـ PII في الـ prompt، وفعّل اتفاقية معالجة بيانات، وراجِع الامتثال قانونياً.
- **سجل التدقيق (`AUDIT`):** كل وصول/تعديل حسّاس (خصوصاً بيانات القضايا والمالية والصلاحيات).
- **عدم تسريب الأسرار:** لا مفاتيح API في الواجهة؛ كلها في Secret Manager.
- **الاحتفاظ والحذف:** سياسة احتفاظ + حذف فعلي عند الطلب (لا مجرد حذف ناعم) امتثالاً للأنظمة.
- **NCA:** راجِع متطلبات الهيئة الوطنية للأمن السيبراني لإقامة البيانات الحسّاسة.

---

## 10. المهام الخلفية

عبر Cloud Tasks/Scheduler: حساب مهل الاعتراض وتذكيراتها، إنشاء مهام ما بعد الجلسة، مسيّر الرواتب الشهري وخصم السُّلف، توليد ملف WPS، تذكير العملاء بالجلسات، فحص تعارض التقويم، وإشعارات الاستحقاق.

---

## 11. النشر والتشغيل

- **Cloud Run** للتطبيق، **Cloud SQL** للقاعدة، **Cloud Storage** للملفات — كلها الدمام.
- **CI/CD:** اختبار + بناء + نشر آلي. بيئات: dev/staging/prod.
- **Migrations:** Prisma migrate ضمن خط النشر.
- **Secrets:** Secret Manager (مفاتيح الذكاء والتكاملات).
- **النسخ الاحتياطي:** نسخ احتياطية مجدولة للقاعدة + اختبار استعادة.

---

## 12. الاختبار والجودة

- **اختبارات وحدة إلزامية لكل قاعدة عمل** في `06-business-rules.md` (VAT، مهلة الاعتراض، الأتعاب، نهاية الخدمة، السعودة، حالة الفاتورة، خصم السُّلف، كشف التعارض).
- اختبارات صلاحيات (يتأكّد أن كل دور يُمنَع فعلاً على الخادم).
- اختبارات e2e للمسارات الحرجة (دخول، فتح قضية، إصدار فاتورة، اعتماد العميل).
- اختبار بوابة التحقق من الاستشهاد (لا يمرّ استشهاد بلا مصدر).

---

## 13. خطة البناء المرحلية (مرتّبة بالاعتماديات)

1. **الأساس:** المشروع + Auth (OTP) + نموذج البيانات الأساسي (cases/clients/users) + الصلاحيات على الخادم + التدقيق.
2. **النواة التشغيلية:** القضايا (المراحل، الجلسات، المسنَدون، النطاق) + كشف التعارض + العملاء/CRM + المهام + المواعيد.
3. **المستندات:** مولّد المستندات + القوالب + PDF + التخزين.
4. **المالية:** الفواتير + VAT + الأتعاب (الأنواع الأربعة) + المصروفات + الأمانات + القيود.
5. **الذكاء (الحرج):** القاعدة المعرفية + RAG + **بوابة التحقق** + المساعد + ساحة المرافعة.
6. **الموارد البشرية:** الرواتب + السُّلف + الإجازات + نهاية الخدمة + السعودة + WPS.
7. **التكاملات:** ناجز → نفاذ → زاتكا → WPS (كل واحد بعقده).
8. **البوّابات:** بوابة العميل + بوابة الموظف.
9. **التهيئة للإطلاق:** تجربة Pilot على مكتبك → إطلاق تدريجي.

> ابدأ بـ MVP (مراحل 1–4) لتجربة حقيقية، ثم 5 (الحرج قانونياً)، ثم العمق والتكاملات.

---

## 14. المخاطر والقرارات المفتوحة

- **الأهم:** جودة وتغطية القاعدة المعرفية القانونية — بدون مصادر كافية، البوابة تحجب كثيراً. يحتاج جهد محتوى قانوني.
- المعالجة عبر الحدود للذكاء مقابل PDPL — يحتاج حسماً قانونياً.
- عقود API الرسمية (ناجز/نفاذ/زاتكا/WPS) — توفّرها وشروطها تحدّد الجدول.
- مزوّد OTP السعودي (Unifonic/واتساب الرسمي) — اختيار وتعاقد.
