# مُرافعة — نموذج البيانات (Data Model)

> **المصدر:** مستخرَج آلياً من `prototype/murafaa-prototype.html` (بيانات mock فعلية)، لا من ذاكرة.
> **الغرض:** المرجع الذي يبني عليه فريق الـ backend مخطّط قاعدة البيانات. كل كيان وحقوله الحقيقية كما هي في النموذج.

## ملاحظة جوهرية للـ backend — قبل أي شيء

النموذج الحالي **يربط الكيانات بالأسماء النصية لا بالمفاتيح** (مثال: الفاتورة تشير للقضية عبر `caseTitle` نصاً، والقضية تشير للعميل عبر الاسم). هذا مقبول في prototype، لكنه **خطأ في الإنتاج**. عند البناء الحقيقي:
- كل كيان له `id` رقمي/UUID كمفتاح أساسي.
- العلاقات عبر **مفاتيح أجنبية (foreign keys)** لا عبر مطابقة الأسماء (`client_id`, `case_id`, `employee_id`).
- الحقول المختصرة أدناه (`n`, `st`, `t`) تُعاد تسميتها لأسماء واضحة في قاعدة البيانات (الجدول أدناه يعطي المعنى).

## الكيانات الأساسية

### `cases` — القضايا (الكيان المركزي)
| الحقل (prototype) | المعنى | النوع | ملاحظات |
|---|---|---|---|
| `id` | معرّف | int | PK |
| `no` | رقم القضية | string | رقم العرض |
| `name` / `title` | اسم/عنوان القضية | string | |
| `entity` | **الموكّل** (عميلنا) | string→FK | يربط بـ `CLIENTS` |
| `party` | **الطرف الآخر / الخصم** | string | محور كشف التعارض |
| `city` | المدينة | enum | من `CITIES` |
| `mainClass`/`subClass`/`caseType` | التصنيف الرئيسي/الفرعي/النوع | enum | تصنيف ناجز (`NAJIZ`) |
| `stage` | المرحلة الإجرائية | enum | من `PROC_STAGES` |
| `status` | الحالة | enum | (جارية/متوقفة/مغلقة…) |
| `hearings[]` | الجلسات | array | كائنات جلسة (نوع من `HEARING_KINDS` + تاريخ) |
| `objectionDue` | مهلة الاعتراض | date | = تاريخ الحكم + 30 يوم (انظر وثيقة القواعد) |
| `assignees[]` | المسنَدون | array→FK | يربط بـ `USERS`/`EMPLOYEES` (علاقة *—*) |
| `fee` | اتفاقية الأتعاب | object | `{type, value, awarded, …}` — 4 أنواع |
| `timeline`/`hist` | الخط الزمني والسجل | array | أحداث القضية |
| `outcome`/`result`/`verdict` | المآل | enum | (كسب/جزئي/تسوية/خسارة) |
| `minutes` | محاضر | array | |
| `csat` | رضا العميل | number | |
| `referral` | جهة الإحالة | string | |
| `archived` | مؤرشفة | bool | للأرشفة الناعمة |
| `clientReport`/`reportSent` | تقرير العميل وحالة إرساله | mixed | لبوابة العميل |

**العلاقات:** `cases` 1—* `hearings` (مضمّنة) · `cases` *—* `USERS`/`EMPLOYEES` (المسنَدون) · `cases` 1—1 `fee` · `cases` 1—* `INVOICES`/`TIME_ENTRIES`/`EXPENSES` · `cases` ← `LEADS` (عبر `convertLead`).

### `CLIENTS` — العملاء
`n` (الاسم) · `phone` (الجوال) · `city` (المدينة) · `st` (الحالة) · `t` (النوع: فرد/شركة) · `cases` (قضاياه).
**علاقة:** `CLIENTS` 1—* `cases` (حالياً بالاسم؛ المطلوب FK).

### `LEADS` — العملاء المحتملون (CRM)
`n` · `type` (النوع) · `src` (المصدر) · `st` (المرحلة في خط الأنابيب) · `val` (القيمة المتوقعة) · `next` (الإجراء التالي).
مخزّنة ككائن مفاتيحه مراحل خط الأنابيب → مصفوفة عملاء لكل مرحلة. يتحوّل العميل المحتمل لقضية عبر `convertLead`.

### `USERS` — مستخدمو بوابة المكتب
`n` · `phone` · `role` (الدور — من الأدوار الستة، انظر وثيقة الصلاحيات).

### `EMPLOYEES` — الموظفون (HR)
`n` · `dept` (القسم) · `role` (الدور) · `basic` (الراتب الأساسي) · `allow` (البدلات) · `gosi` (اشتراك التأمينات) · `join` (تاريخ الالتحاق) · `leaveBal` (رصيد الإجازات) · `perf` (تقييم الأداء) · `st` (الحالة).
بيانات إضافية في `EMP_EXTRA` (الجنسية `nat`، سنة الالتحاق `joinY` — تُستخدم في نهاية الخدمة والسعودة).
**علاقات:** `EMPLOYEES` 1—* `ADVANCES`/`LEAVES`/`EMP_REQUESTS`/`PAYROLL_RUNS`.

## الكيانات المالية

### `INVOICES` — الفواتير
`no` (الرقم) · `client` · `date` · `net` (الصافي) · `vat` (الضريبة 15%) · `total` (الإجمالي) · `st` (الحالة — تُشتق عبر `invStatusOf`: مدفوعة/جزئياً/مستحقة/متأخرة/دين معدوم).
**علاقة:** `INVOICES` 1—* `INV_ITEMS` (بنود الفاتورة).

### `INV_ITEMS` — بنود الفواتير
بنود السطر لكل فاتورة (وصف/كمية/سعر) — تُجمَع في `invItemsTotals`.

### `EXPENSES` — المصروفات
`id` · `vendor` (المورّد) · `cat` (الفئة من `EXP_CATS`) · `amount` · `vat` · `date` · `caseTitle` (القضية) · `client` · `billable` (قابل للفوترة) · `billed` (تم تحميله للعميل) · `method` (طريقة الدفع) · `recurring` (متكرر).
المصروف القابل للفوترة يتحوّل لفاتورة استرداد عبر `expReinvoice`.

### `TIME_ENTRIES` — تسجيل الوقت
`id` · `lawyer` · `caseTitle` · `desc` · `hours` · `rate` · `date` · `billable` · `invoiced`.
أساس احتساب أتعاب «بالساعة»: الساعات غير المفوترة × السعر.

### `TRUST` — أمانات العملاء (حساب العهدة)
`id` · `client` · `amount` · `type` · `date` · `note` · `txns` (الحركات). **يُفصَل محاسبياً عن إيرادات المكتب.**

### دفاتر محاسبية مرجعية
`COA`/`ACCOUNTS` (شجرة الحسابات) · `JOURNAL` (القيود) · `TRIAL` (ميزان المراجعة) · `AGING` (أعمار الديون) · `CREDIT_NOTES` (الإشعارات الدائنة) · `FIN_TX`/`FIN_KPIS`/`FIN_BARS` (حركات ومؤشّرات اللوحة).

## كيانات الموارد البشرية

### `ADVANCES` — السُّلف
`id` · `emp` · `amount` · `monthly` (القسط الشهري) · `months` (عدد الأشهر) · `paid` (المدفوع) · `date` · `status` · `note`. الخصم الشهري عبر `advMonthlyOf`، المتبقّي عبر `advRemaining`.

### `LEAVES` — الإجازات
`n` (الموظف) · `type` (النوع) · `days` (الأيام) · `when` (التاريخ). تُخصَم من `leaveBal`.

### `EMP_REQUESTS` — طلبات الموظفين
`id` · `emp` · `dept` · `kind` (النوع) · `detail` · `days` · `stage` · `status` · `hist` (سجل المعالجة).

### `PAYROLL_RUNS` — مسيّرات الرواتب
تُولَّد وقت التشغيل عبر `payRunMonth`/`payRunAdvance` (ليست بيانات ثابتة). تشمل الأساسي + البدلات − GOSI − خصم السُّلف.

### `RECRUIT` — التوظيف
بيانات الوظائف والمرشّحين. يتحوّل طالب الوظيفة من واتساب لمرشّح عبر `waToCandidate`.

## كيانات الاعتمادات والبوّابات

### `PROPOSALS` — طلبات الاعتماد (مذكرة/أتعاب/تسوية)
`id` · `client` · `kind` (النوع) · `val` (القيمة) · `st` (معلّق/معتمد/مرفوض).

### `CLIENT_APPR` — اعتمادات العميل (من بوابة العميل)
`id` · `t` (العنوان) · `note` · `st`. يعتمد/يرفض العميل عبر `cAppApprove`/`cAppReject`.

### `CLIENT_REPORTS` — تقارير العميل
تقارير القضية المنشورة للعميل (تُولَّد ديناميكياً). يفتحها العميل عبر `cpOpenReport`.

### `REPORT_APPROVALS` — اعتمادات التقارير الداخلية
دورة اعتماد التقرير قبل إرساله للعميل.

## البيانات المرجعية (Enums / Lookups)

- `CITIES` — المدن
- `NAJIZ` — تصنيفات ناجز (رئيسي/فرعي/نوع)
- `PROC_STAGES` — مراحل التقاضي: الصلح · الدرجة الأولى · الاستئناف · النقض · التنفيذ
- `HEARING_KINDS` — أنواع الجلسات (10): تمهيدية، مرافعة، تبادل مذكرات، ضبط/إجراءات، سماع شهود، خبرة، حجز للحكم، نطق بالحكم، صلح، أخرى
- `EXEC_STATUS` — حالات التنفيذ: مطلوب · قيد التنفيذ · منفّذ · متعثّر
- `EXEC_PROC_TYPES` / `EXEC_FILE_STATUS` — أنواع وحالات ملفات التنفيذ
- `PROC_REQ_TYPES` / `PROC_REQ_STATUS` — أنواع وحالات الطلبات الإجرائية
- `NITAQAT_BANDS` — نطاقات السعودة (6): بلاتيني/أخضر مرتفع/متوسط/منخفض/أصفر/أحمر
- `EXP_CATS` — فئات المصروفات
- `WA_CATS` — تصنيفات رسائل واتساب
- `INTEGRATIONS` — التكاملات: `id` · `name` · `desc` · `scope` · `status` · `sync` (ناجز/نفاذ/زاتكا/WPS — **محاكاة بصرية، بلا ربط API فعلي**)
- `PLANS` / `PMODULES` — الباقات والوحدات: `id` · `price` · `feats`
- `ARENA_ROLES` / `DEMO_LAWYER` / `DEMO_JUDGE` — أدوار ساحة المرافعة

## توصيات التطبيع للـ backend (ملخّص)

1. **مفاتيح أساسية وأجنبية** لكل كيان بدل الربط بالأسماء.
2. **جدول وصل** لعلاقة `cases ⇄ users` (المسنَدون، *—*).
3. فصل `fee` و`hearings` و`timeline` لجداول مستقلة (حالياً مضمّنة في القضية).
4. حساب الأمانات (`TRUST`) **منفصل** عن الإيرادات في دفتر الأستاذ.
5. الحقول المحسوبة (VAT، حالة الفاتورة، مهلة الاعتراض، نهاية الخدمة) تُطبَّق كقواعد في الـ backend — انظر `06-business-rules.md`.
6. كل كيان يحتاج حقول تدقيق: `created_at`, `updated_at`, `created_by`, `deleted_at` (للحذف الناعم).
