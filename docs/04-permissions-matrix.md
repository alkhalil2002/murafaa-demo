# مُرافعة — مصفوفة الصلاحيات (Permissions Matrix)

> **المصدر:** مستخرَج آلياً من `prototype/murafaa-prototype.html` (`PROLES`, `PSEED`, `PERM`, `FIELD_DENY`, `CASE_SCOPE`, `VIEW2MOD`, `FREE_VIEWS`).
> **الغرض:** المرجع الكامل لنظام الصلاحيات — الأدوار، الوحدات، المستويات، وطبقات الفرض الثلاث.

## ⚠️ قيد إلزامي للـ backend (اقرأه أولاً)

في النموذج الحالي **الصلاحيات واجهية فقط**: المصفوفة تُخفي الشاشات والحقول عبر CSS وشروط العرض، لكنها **لا تمنع الوصول للبيانات فعلياً**. كما يوجد «god mode»: إذا لم يكن هناك دور جلسة (`SESSION_ROLE` فارغ) فالمالك يرى كل شيء.

**في النسخة الحقيقية:** كل قرار صلاحية **يُفرَض على مستوى الـ backend/API** (وصول الوحدة + الحقل + الصف)، لا على الواجهة. الواجهة تُخفي فقط؛ الخادم يمنع. هذا غير قابل للتفاوض لأن المنتج قانوني ويحمل بيانات حسّاسة.

## الأدوار الستة (`PROLES`)

| # | الدور | الوصف |
|---|---|---|
| 1 | **شريك** | صلاحية كاملة على كل الوحدات |
| 2 | **محامي** | تشغيل القضايا والمستندات والمواعيد؛ اطّلاع على المالية محدود |
| 3 | **مساعد** | دعم القضايا والمستندات والمهام؛ **ممنوع من بيانات الأتعاب** |
| 4 | **محاسب** | المالية فقط (كامل) + اطّلاع على التقارير |
| 5 | **إداري** | الموارد البشرية والعملاء والمواعيد والمهام |
| 6 | **موظف استقبال** | واتساب والمواعيد (كامل) + العملاء |

## مستويات الصلاحية

`none` (لا وصول) ← `view` (اطّلاع فقط) ← `edit` (إضافة/تعديل) ← `full` (يشمل الحذف والإجراءات الحسّاسة).

## الوحدات الـ13 المتحكَّم بها (`PMODULES`)

القضايا · المحاكمة الذكية · العملاء (CRM) · المستندات · المالية · الموارد البشرية · التقارير · الصلاحيات · واتساب · المواعيد · المهام · التنبيهات · نبض الفريق.

## طبقات الفرض الثلاث

### الطبقة 1 — وصول الوحدة/الشاشة (`can` + `VIEW2MOD`)
كل شاشة تُربَط بوحدة عبر `VIEW2MOD`، ثم يُفحَص مستوى الدور في `PERM`:
- `can(view, "v")` للاطّلاع · `can(view, "edit")` / `"del"` للإجراءات.
- **خريطة الربط:** cases/workspace→القضايا · copilot→المحاكمة الذكية · clients→العملاء · documents/kb→المستندات · finance/billing→المالية · hr→الموارد البشرية · journey/activity→التقارير · perms→الصلاحيات · whatsapp→واتساب · deadlines→المواعيد · tasks→المهام · alerts→التنبيهات · pulse→نبض الفريق.
- **شاشات حرة (`FREE_VIEWS`)** متاحة للجميع دائماً: today · dashboard · settings · notifications · clientportal · empportal.

### الطبقة 2 — منع الحقل (`canField` + `FIELD_DENY`)
منع حقول بعينها داخل شاشة متاحة. القاعدة الحالية:
```
FIELD_DENY = { "مساعد": ["fees"] }
```
أي: **المساعد يدخل القضية لكنه لا يرى بيانات الأتعاب.** `canField("fees")` ترجع false له.

### الطبقة 3 — نطاق الصفوف (`caseVisible` + `CASE_SCOPE`)
تحكّم في أيّ **القضايا** يراها الدور:
- `all` — كل القضايا.
- `assigned` — المُسنَدة إليه فقط (يُفحَص وجود المستخدم في `case.assignees`).
- تُطبَّق على: قائمة القضايا، فتح القضية، والعدّادات. تُضبَط من شاشة الصلاحيات (`setRoleScope`).

## متطلبات الـ backend لإعادة بناء النظام

1. جدول `roles` + جدول `permissions` (role × module × level) قابل للتحرير.
2. جدول `field_permissions` (role × resource × field → allow/deny).
3. سياسة نطاق الصفوف (row-level scope) لكل دور على القضايا (وقابلة للتوسعة لكيانات أخرى).
4. **فرض الطبقات الثلاث في طبقة الـ API/الخدمة**، مع رفض أي طلب غير مصرّح (لا اعتماد على إخفاء الواجهة).
5. إلغاء «god mode»: كل جلسة لها دور صريح؛ صلاحيات المالك تُمنَح عبر دور «شريك» لا عبر غياب الدور.
6. تسجيل كل قرار رفض/سماح حسّاس في `AUDIT`.
